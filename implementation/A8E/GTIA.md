# GTIA

> Hardware emulation reference: Before implementing any Atari 800 XL PAL machine related hardware emulation, use the [AHRM](/AHRM/index.md) as reference.

- Files: `A8E/Gtia.c`, `A8E/Gtia.h`, `A8E/AtariIo.c`, `A8E/tests/antic_graphics_modes_probe.c`
- Purpose: render player/missile behavior and resolve priorities/collisions.
- Status: updated on 2026-09-22 (`implemented`).
- Notes: register writes are handled in `Gtia.c`; color resolve, player/missile priority, and collision updates are applied during per-line draw in `AtariIo.c`. Each color clock with an active player or missile is colored by `AtariIo_ResolvePriorityClock` from the AHRM 6.7 equations (`AtariIo_PrioritySelect`): missiles join their players (or PF3 with the fifth player), the selected color registers are ORed ($00 when nothing is selected, the background keeps the rendered COLBK/GTIA color), so PRIOR[3:0]=0 mixes PF0/PF1 with P0/P1 and PF2/PF3 with P2/P3, multicolor mode blends M0+M1/M2+M3 as well, and conflicting priority bits give the Table 16 black. In hires modes the logic sees PF2 and the PF1 luminance is impressed on the 1-bits afterwards (AHRM 6.8). Collisions still use the raw signals. PMG DMA is managed by the unified `AtariIo_FetchPmgDmaCycle` helper, called from `AtariIo_DrawClockAction` at the documented cycle slots (missile at cycle 0, players 0–3 at cycles 2–5). `VDELAY` masks even-scanline fetches instead of shifting PMG memory rows; missile DMA stays active when player DMA is enabled (AHRM 4.13). Interleaved PMG rendering now uses a per-line shift-register/state-machine model: a trigger ORs new latch data into the active shifter, resets the size state to `%00`, and allows repeated rightward same-line retriggers without moving an already-started image. PM horizontal origin uses the same AHRM 6.2 coordinate mapping as playfield rendering, so HPOS `$30` aligns with the normal playfield left edge at line-buffer `x=96`. `PMBASE` is read live at each DMA cycle — a DLI write between cycles 5 and 0 of adjacent scanlines takes effect cleanly on the next scanline; a write during cycles 0–5 causes a mixed-base fetch for that scanline (matching real hardware behavior).
- Issues: the interleaved PMG path still reconstructs the hidden portion of a line from current register state when the first visible span is drawn, rather than replaying every earlier same-line register write cycle by cycle. GTIA mode 10 pixels are treated as background for priority and collisions (AHRM 6.9 has codes 0-3 act as P0-P3). The legacy non-interleaved `AtariIoDrawPlayerMissiles` and the `AtariIo_Draw*Span` helpers are unused and still carry the old mask priorities.
